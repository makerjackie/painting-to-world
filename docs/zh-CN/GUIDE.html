使用指南

先体验，再创作

解压整个包，打开根目录 START-HERE.html。两个案例均有中文/英文入口，进入后也能切换语言。examples/cafe-terrace/archive/index.html 是原始成功案例的未改动存档；当前入口额外补齐了本地化细节。

电脑操作：拖动环顾，WASD 或方向键移动，F 步行/飞行，飞行时 Q 下降、E 上升；H 隐藏/恢复界面；P 导出带边框的实际 PNG。地点栏可以快速抵达不同位置。手机提供摇杆、拖动环顾、飞行升降按钮。

咖啡座在点击进入后启动轻柔配乐，可立即关闭；《呐喊》的配乐默认关闭，需要单独点击。两者都支持关闭自动运镜。碰撞仅约束步行，飞行不模拟真实身体。

你需要什么

创作阶段需要能看图、读取完整 Skill、读写本地文件并写代码的 AI；构建脚本需要 Node.js 18+。视觉验收需要可用的 WebGL2 浏览器。Playwright/Python 只用于可选自动化检查，不是网站运行依赖。缺少浏览器时可产出代码，但不得宣称做过视觉验收。

本包不附带 AI 账号、付费额度、第三方模型权重、在线上传页面或托管服务器。直接打开案例只是体验成品；修改为新画作仍需要 AI 执行 Skill。

安装：只选一份语言版

中文：skills/zh-CN/painting-to-world/。英文：skills/en/painting-to-world/。两份有同样的功能和独立工程资源，不要把同名中英文 Skill 同时安装进同一个作用域。

适用于支持本地 Agent Skills 的环境。以 Codex 的项目级目录为例，把整份目录放在项目的 .agents/skills/painting-to-world/；用户级位置是 ~/.agents/skills/painting-to-world/。具体发现与重新加载行为以所用客户端版本为准。官方位置说明见文末来源。

macOS/Linux 示例（在解压后的包根目录执行，把路径改为自己的项目）：

DEST="/path/to/your-project/.agents/skills/painting-to-world"
if [ -e "$DEST" ]; then
  echo "目标已存在，请先检查并备份，不要直接覆盖。"
else
  mkdir -p "$(dirname "$DEST")"
  cp -R skills/zh-CN/painting-to-world "$DEST"
fi

Windows 也可用文件管理器复制整个目录，不需要执行 shell。此包没有在你的机器上自动安装任何内容。

在没有本地 Skill 发现机制、但可读取附件和执行代码的环境中，将整份目录或本包作为工作资料提供，明确让 AI 先读 SKILL.md 和引用文件。仅上传压缩包并不保证每个聊天客户端自动安装或执行；不支持文件写入/代码执行的纯聊天模式也不能凭此运行构建脚本。

上传参考与发起任务

提供一张清晰、边界完整的 JPG/PNG/WEBP，优先保留原始长宽比。若有同名不同版本，请注明画家、画名、年份或馆藏来源。不要把拼图、广告截屏、含大块遮挡的图片当精确构图参考。不要提供无权上传到外部服务的私人图片。

在支持显式 Skill 调用的环境中，选中 painting-to-world 或按客户端方式引用。提示词：

请使用 painting-to-world Skill，把我上传的画作做成一个可漫游的 3D 网站。
参考图就是本次上传的图片，不要自动换成别的版本。
先记录构图、主要识别点、色彩与笔触，再选择适合这幅画的空间表达。
以咖啡座案例的工程质量为基准，重新实现主体与场景，不要只改咖啡座配色。
先有自动导览，再允许自由漫游；支持中英文、电脑和手机、配乐开关与截图。
必须查看实际浏览器截图并修复，不能用概念图代替运行结果。
最终给我离线 HTML、可编辑源码、使用说明、来源与检查报告，统一 ZIP 交付。
普通制作决策不必询问我；输入缺失或权利不明确时明确指出。

可选：先复制工程底座

在本包根目录运行：

node skills/zh-CN/painting-to-world/scripts/init.mjs ./my-painting --reference ./my-reference.png
node my-painting/scripts/build.mjs

初始化脚本拒绝覆盖非空目录，只复制工作底座、参考图和分析模板。这时打开的仍然是咖啡座。 它没有分析图片，也没有生成新的几何；下一步需让 AI 按 Skill 改写 world.js、textures.js、镜头与文案。不要把初始化成功宣传为新画作已完成。

如何改得更像

不要一次让 AI “再精致一点”。指出参考画中三至七个关键差异，例如：主体横向位置、占画幅比例、栏杆消失点、前景遮挡、黄蓝对照、天空笔触方向。先修构图和主轮廓，再补细节。要求保存同视角前后截图，并在反向/侧向视角验证真实三维体积。

风景、街景与室内适合连续步行空间。肖像、静物、毕加索式多视角画面可能更适合雕塑展台或空间装置；深度浮雕也可以，但必须明确其视角范围，不能叫完整 360° 世界。一张图不能确定所有背面。

交付和发布

确认输出至少有 index.html、index.en.html、完整 src/、scripts/build.mjs、双语说明、来源、QA 和实际截图。先运行构建与静态检查，再打开验证。

node scripts/build-all.mjs
node scripts/check-package.mjs

本包可以放到你选定的静态托管服务上；具体发布需要该服务的账号、权限与配置。没有自动建立线上地址。使用自己有权使用的原画图像和素材，正式售卖前另行确定许可、支持、更新与退款说明。

常见问题

为什么新画作还是咖啡座？ 只执行了脚手架复制，还没让 AI 重写场景。

为什么结果变成截图/全景？ 让 AI 回到 Skill 的真实几何门槛：侧移应出现视差和新露出的物体侧面，主对象不能只是始终面向镜头的图片。

为什么宣传图比运行画面好看？ 历史 AI 概念海报不能当性能或效果证据。使用 marketing/zh-CN/ 中本轮实机截图排版的正式图片，保留边界说明。

能保证每张画都一次复刻吗？ 不能作这样的保证。Skill 提高执行一致性，但质量仍受参考图、AI、工具、空间方案和迭代影响。

中文和英文要装两次吗？ 不需要。任选一个 Skill；生成的案例本身应提供双语。
